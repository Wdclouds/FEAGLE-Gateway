## 1. 漏斗流水线分层架构原理

微信群聊环境具有“消息并发高、闲聊杂讯多、长任务易烧额度、易遭攻击试探”的特点。若直接将收到的所有消息无差别调用大模型，不仅调用成本极其高昂，响应延迟也会剧烈劣化。

网关设计了**四层漏斗流水线（Funneling Pipeline）**，每一层承担特定的过滤和分流职责：

```text
[新消息入站] ──> [滑动窗口防抖 (2.5秒聚合同用户连续打字断句)]
                         │
                         ▼
┌────────────────────────────────────────────────────────┐
│ L0 规则拦截与硬指令层 (0 Token, 0 延迟, 纯 TypeScript)   │
│ • 硬指令集秒级匹配 (/help, /mode, /status, /cron...)   │
│ • 越狱攻击与提示词投毒检测 (isPromptInjectionOrToxic)   │
│ • 敏感操作挂起审批优先裁决 (审批未决前阻断新交互)     │
│ • 运行模式过滤: mute (彻底静音) / sentry (只听不答)   │
└────────────────────────┬───────────────────────────────┘
                         │ (未命中 L0，放行至 L1)
                         ▼
┌────────────────────────────────────────────────────────┐
│ L1 智能语义路由与直答层 (Gemini 3.8 Flash, 延迟 < 1.5s)│
│ • 意图决策单字母分流 (W/S/X/T/C/R)                     │
│ • 额度熔断保护 (R: 识别超大规模需求并礼貌拒绝/拆解)   │
│ • 闲聊与即时问答 (T: 结合 15分钟衰减环与背景感知直答)  │
│ • 原生多模态视觉转述 (自动识别图片 base64 转述为上下文)│
│ • 哨兵模式离线语义提取 (紧急告警直推 OP, 社交图谱沉淀) │
└────────────────────────┬───────────────────────────────┘
                         │ (仅当 decision='C' 且人设支持工程执行时)
                         ▼
┌────────────────────────────────────────────────────────┐
│ L2 复杂任务引擎与 Pi 单例调度 (Pi CLI Sub-process)      │
│ • 本地文件读写、Shell 脚本执行、Git 版本库操作         │
│ • 全局单例保护 + 租约锁 (Lease)，杜绝并发踩踏          │
│ • 闲置 3 分钟自动焚毁回收内存 (V8 256MB 硬限)          │
│ • 遇到高危操作拦截并触发 120s 微信审批挂起             │
└────────────────────────┬───────────────────────────────┘
                         │ (生成最终待发文本 / 工具生成待发图片)
                         ▼
┌────────────────────────────────────────────────────────┐
│ L3 出站合成与防风控直发层 (Outbound Delivery)           │
│ • 微信原生引用回复气泡包装 (formatQuoteReply)          │
│ • 敏感凭证与绝对路径自动脱敏 (desensitize)             │
│ • 语义无损分片切分 (splitChunks: 段落/标点优先切分)    │
│ • 拟人化随机延迟注入 (300ms ~ 1500ms 随机等待防风控)   │
│ • 构造批次抛送至 Bridge :6192 串行发出                 │
└────────────────────────────────────────────────────────┘
```

## 2. L0 规则拦截与硬指令集规格

所有以 `/` 开头的指令均在 L0 层拦截，即使在群聊中以 `@Nox /cmd` 或 `@Nox/cmd` 形式出现，网关也会在进站时自动剥离提及前缀，秒级命中并返回。

### 2.1 全量指令手册

| 指令名称 | 权限要求 | 语法与参数 | 行为描述与返回规格 |
|---|---|---|---|
| `/help` | 所有人 | `/help` | 列出当前角色与权限可执行的所有指令清单、功能说明与操作指引。 |
| `/sid` | 所有人 | `/sid` | 打印当前会话的统一 ID、发信人 wxid、发信人昵称、群/私聊类型、权限角色与当前模式。 |
| `/stats` | 所有人 | `/stats` | 检索 SQLite 数据库，展示全系统累计会话数、Traces 流水数、以及本会话的互动统计。 |
| `/history` | 所有人 | `/history` | 打印当前会话 15 分钟衰减环内已记录的多轮问答历史以及防抖缓冲队列。 |
| `/mode` | 所有人 | `/mode [chat\|sentry\|mute]` | 切换当前会话模式：<br>• `chat`：正常交互应答；<br>• `sentry`：哨兵模式（静默监听，仅识别紧急警报并私聊通知 OP，提取人际图谱入库）；<br>• `mute`：大模型彻底静默。 |
| `/block` | 管理员 (OP) | `/block <wxid\|群ID> [原因]` | 将指定用户或群聊加入黑名单，网关层静默丢弃其所有消息。管理员不可被屏蔽。 |
| `/unblock` | 管理员 (OP) | `/unblock <wxid\|群ID>` | 从黑名单中移除指定目标，恢复消息交互。 |
| `/name` | 管理员 (OP) | `/name <自定义别名>` | 为当前会话设置或更新可读别名，持久化写入沙箱 `meta.json`。 |
| `/op` | 管理员 (OP) | `/op <wxid>` | 在线为指定用户赋予管理员权限（写入 `config.adminWxids` 与持久化存储）。 |
| `/deop` | 管理员 (OP) | `/deop <wxid>` | 撤销指定用户的管理员权限（不可自撤）。 |
| `/save` | 管理员 (OP) | `/save <快照名称>` | 抓取当前 Git 工作区状态、HEAD 提交与上下文，写入 Mnemosyne 记忆宫殿。 |
| `/load` | 管理员 (OP) | `/load <快照名称>` | 从记忆宫殿调取指定快照，注入当前会话并恢复工作区。 |
| `/cd` | 管理员 (OP) | `/cd <绝对路径>` | 动态变更底座 Pi 的执行工作目录；若当前进程空闲则触发立即回收以便重置目录。 |
| `/cron` | 管理员 (OP) | `/cron list\|add\|del` | 定时任务管理。支持 Cron 5 段表达式或相对毫秒调度（如 `/cron add daily 0 9 * * 1-5 晨会提醒`）。 |
| `/audit` | 管理员 (OP) | `/audit [条数]` | 反查系统审计日志表 `trace_logs` 最近 N 条流水，显示放行状态与风险标记。 |
| `/approve` | 管理员 (OP) | `/approve` | 针对当前挂起的高危命令审批申请发放 60 秒临时金牌特权并唤醒任务。 |
| `/deny` | 管理员 (OP) | `/deny` | 显式拒绝当前挂起的高危命令审批，终止任务执行。 |
| `/prune` | 管理员 (OP) | `/prune` | 联动 Bridge 清理已退出的无效群聊和历史测试实体。 |

### 2.2 提示词投毒与越狱防火墙 (`isPromptInjectionOrToxic`)
在进入大模型前，L0 层使用纯正则与词根分析器拦截潜在安全威胁：
* 忽略指令前置（`ignore previous instructions`、`disregard all prior system prompts`）；
* 角色扮演越狱（`DAN mode`、`jailbreak`、`you are now uncensored`）；
* 敏感文件与系统漏洞探测（`cat /etc/passwd`、`rm -rf /`、反弹 Shell 尝试）；
* 一旦触发，直接在 L0 层以“安全规则拦截”拒绝，零 Token 损耗。

## 3. L1 语义路由与额度熔断保护 (Quota Guard)

### 3.1 单字母意图路由协议
L1 采用轻量极速模型（Gemini 3.8 Flash），对用户消息进行意图裁决，并输出单字母路由决策：

```text
       ┌───────────┐
       │ 用户输入  │
       └─────┬─────┘
             ▼
     ┌───────────────┐
     │  L1 意图判决  │
     └───────┬───────┘
  ┌─────┬────┼────┬─────┬─────┐
  ▼     ▼    ▼    ▼     ▼     ▼
  W     S    X    T     C     R
等待  追加 中止  闲聊  工程  熔断
```

* **W (Wait)**：断句等待。检测到用户话未讲完（如“首先第一点...然后”或末尾有未闭合列表），滑动窗口延长 2.5 秒等待下一段消息拼接。
* **S (Steer)**：过程修正。当后台已有工程任务正在执行时，用户发送补充要求（如“改用 TypeScript 别用 JS”），直接追加到现有会话中纠偏，不重新开辟进程。
* **X (Cancel)**：中止取消。用户发出“算了/别做了/停止/终止”，立刻杀死后台 Pi 子进程并释放租约锁。
* **T (Talk)**：即时闲聊/问答。包括情感交流、简短知识检索，由 Gemini 3.8 Flash 结合当前群人设与历史会话秒级直答。
* **C (Coding/Engineering)**：复杂工程任务。确凿的代码修改、文件排查、Shell 执行，转入 L2 处理。
* **R (Refuse 额度保护)**：**系统最具特色的防爆机制**。当大模型识别到提问规模庞大、需要海量 Token 或全栈代码开发时，L1 自动拦截并给出礼貌拒绝与分步骤拆解建议，**坚决不调用 L2，避免瞬间烧尽 API 额度**。

## 4. 15分钟自然衰减会话环与群聊背景感知

### 4.1 15 分钟自然衰减会话环 (`DialogManager`)
传统微信机器人要么无多轮记忆（一问一答），要么记忆无限膨胀最终爆 Token 崩溃。

FEAGLE 网关提出了 **15 分钟自然衰减会话环**：
* 维护每个群的会话环：`dialogManager.getTurns(chatId)`。
* 当群友向机器人提问时，系统记录提问与回复，并为该会话重置 **900 秒（15 分钟）倒计时**。
* 在 15 分钟窗口内，后续提问自动带上历史上下文（最多保留 8 条/4 轮对话）。
* 一旦群内超过 15 分钟无人与机器人互动，该会话环自动失效清空。下一次提问从全新上下文冷启动。这既保证了高频互动的连贯性，又杜绝了跨越半天之后的上下文混乱。

### 4.2 群聊背景感知环 (Rolling 20 Buffer)
在微信群聊中，群友经常在连续闲聊某件事后，突然 `@Nox` 询问“你觉得他们说得对吗？”。

为了在**不随意打扰群聊**的前提下赋予机器人这种情境感知能力：
1. 群内所有普通发言（即使没有 `@Nox`）会被悄悄推入一个**容量为 20 条的滑动缓冲区**（只保留最近 20 条，老消息自动淘汰，不持久化入库）；
2. 当群友正式 `@Nox` 提问时，网关将这 20 条最新背景信息以只读的形式封装注入 System Prompt：
   ```text
   [当前群聊最近背景闲聊流水 (仅供参考上下文，禁止直接逐条应答)]
   张三: 这个前端构建好像有内存泄露
   李四: 我看 node 进程都吃到了 2GB
   ```
3. 机器人便能瞬间领悟群友所指，做出精准解答。

## 5. L2 工程执行层与 Pi 单例调度

### 5.1 单例保护与租约锁机制 (`PiManager`)
为了防止高并发下多个会话同时执行后台代码导致服务器 CPU/内存雪崩：
* 全局维持一个由 `PiManager` 托管的单例执行引擎；
* **租约锁 (Lease)**：同一时间只允许一个会话持有执行租约。其他会话的重型工程请求将被排队等待或转入 L1 降级问答；
* **V8 256MB 内存硬限**：主子进程启动时严格注入 `--max-old-space-size=256` 参数；
* **闲置 3 分钟自动焚毁**：当一个工程任务结束后，若在 180 秒内没有新任务进站，Pi 子进程将执行优雅退出并被系统回收，释放全部宿主内存。

### 5.2 敏感操作 120 秒双向审批机制
当 Pi 在执行代码时触碰危险边界（如删除文件、修改生产配置、执行未知网络请求）：
1. 任务自动挂起（Hold）；
2. 网关向当前会话与管理员群抛出高危审批卡片：“检测到高危命令 `[rm -rf build]`，请在 120 秒内回复 `Y` 放行，回复 `N` 终止”；
3. 管理员可在微信端直接发送 `/approve` 或回复 `Y`，网关核销审批并颁发 60 秒临时安全令牌继续执行；若超时未批，自动拒绝并安全回滚。

## 6. L3 出站合成与拟人防风控直发

### 6.1 微信原生引用回复气泡 (`formatQuoteReply`)
在热闹的百人群聊中，如果机器人直接在群内抛出答案，群友很难分清是对谁的解答。

FEAGLE 网关在 L3 层实现了**原生引用回复协议**：
* 提取进站消息的 `msgSvrId`、发件人昵称和提问摘要；
* 格式化输出带有专属微信标记的气泡头，在微信手机端展现为高亮引用小框，提升群友阅读体验。

### 6.2 敏感数据脱敏 (`desensitize`)
在将大模型输出推向微信通道前，必须经过脱敏层净化：
* 自动消除包含的 API Key、Bearer Token、阿里云 AK/SK 等凭据；
* 自动将生产服务器绝对路径（如 `/opt/FEAGLEwxbot/data/...`）映射替换为抽象工程路径，杜绝内网拓扑泄露。

### 6.3 语义无损分片与拟人随机等待
* **切片算法 (`splitChunks`)**：微信单条消息过长（超过 800 字）容易引人反感或触发折叠。网关在换行符、句号等自然语言断句处优先分片，避免将一句代码或一个词切断；
* **拟人化抖动等待 (Jitter)**：各分片之间不进行瞬间并发爆轰，而是按长度注入 **800ms ~ 1500ms 的随机拟人延迟**，完美模拟真人打字节奏，彻底规避微信防机器人发信频控风控。
